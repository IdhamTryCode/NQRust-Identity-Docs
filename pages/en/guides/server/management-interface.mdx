# Configuring the Management Interface

import { Callout } from 'nextra/components'

The management interface allows accessing management endpoints via a different HTTP server than the primary one.
It provides the possibility to hide endpoints like `/metrics` or `/health` from the outside world and, therefore, hardens the security.
The most significant advantage might be seen in Kubernetes environments as the specific management port might not be exposed.

## Management interface configuration

The management interface is turned on when something is exposed on it.
Management endpoints such as `/metrics` and `/health` are exposed on the default management port `9000` when metrics and health are enabled.
The management interface provides a set of options and is fully configurable.

<Callout type="info">
  If management interface properties are not explicitly set, their values are automatically inherited from the default HTTP server.
</Callout>

### Port

In order to change the port for the management interface, you can use the NQRust-Identity option `http-management-port`.

### Relative path

You can change the relative path of the management interface, as the prefix path for the management endpoints can be different.
You can achieve it via the NQRust-Identity option `http-management-relative-path`.

For instance, if you set the CLI option `--http-management-relative-path=/management`, the metrics, and health endpoints will be accessed on the `/management/metrics` and `/management/health` paths.

User is automatically **redirected** to the path where NQRust-Identity is hosted when the relative path is specified.
It means when the relative path is set to `/management`, and the user access `localhost:9000/`, the page is redirected to `localhost:9000/management`.

<Callout type="info">
  If you do not explicitly set the value for it, the value from the http-relative-path property is used. For instance,
  if you set the CLI option --http-relative-path=/auth, these endpoints are accessible on the /auth/metrics and /auth/health paths.
</Callout>

### TLS support

When the TLS is set for the default NQRust-Identity server, by default the management interface will be accessible through HTTPS as well.
The management interface can run only either on HTTP or HTTPS, not both as for the main server.

<Callout type="info">
  If you do not want the management interface to use HTTPS, you may set the http-management-scheme option to http.
</Callout>

Specific NQRust-Identity management interface options with the prefix `https-management-*` were provided for setting different TLS parameters for the management HTTP server. Their function is similar to their counterparts for the main HTTP server, for details see [Configuring TLS](/en/guides/server/enabletls).
When these options are not explicitly set, the TLS parameters are inherited from the default HTTP server.

### Disable Management interface

The management interface is automatically turned off when nothing is exposed on it.
Currently, only health checks and metrics are exposed on the management interface regardless.
If you want to disable exposing them on the management interface, set the NQRust-Identity property `legacy-observability-interface` to `true`.

<Callout type="warning">
  Exposing health and metrics endpoints on the default server is not recommended for security reasons, and you should always use the management interface.
  Beware, the `legacy-observability-interface` option is deprecated and will be removed in future releases.
  It only allows you to give more time for the migration.
</Callout>

## Relevant options

| Option | _Type_ or Values | Default |
| --- | --- | --- |
| **`http-management-health-enabled`**<br/>If health endpoints should be exposed on the management interface.<br/>If false, health endpoints will be exposed on the main interface.<br/>**CLI:** `--http-management-health-enabled`<br/>**Env:** `KC_HTTP_MANAGEMENT_HEALTH_ENABLED` | `true`, `false` | `true` |
| **`http-management-port`**<br/>Port of the management interface.<br/>Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--http-management-port`<br/>**Env:** `KC_HTTP_MANAGEMENT_PORT` | _Integer_ | `9000` |
| **`http-management-relative-path`**<br/>Set the path relative to / for serving resources from management interface.<br/>The path must start with a `/`. If not given, the value is inherited from HTTP options. Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--http-management-relative-path`<br/>**Env:** `KC_HTTP_MANAGEMENT_RELATIVE_PATH` | _String_ | `/` |
| **`http-management-scheme`**<br/>Configures the management interface scheme.<br/>If `inherited`, the management interface will inherit the HTTPS settings of the main interface. If `http`, the management interface will be accessible via HTTP - it will not inherit HTTPS settings and cannot be configured for HTTPS.<br/>**CLI:** `--http-management-scheme`<br/>**Env:** `KC_HTTP_MANAGEMENT_SCHEME` | `http`, `inherited` | `inherited` |
| **`https-management-certificate-file`**<br/>The file path to a server certificate or certificate chain in PEM format for the management server.<br/>If not given, the value is inherited from HTTP options. Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--https-management-certificate-file`<br/>**Env:** `KC_HTTPS_MANAGEMENT_CERTIFICATE_FILE` | _File_ |  |
| **`https-management-certificate-key-file`**<br/>The file path to a private key in PEM format for the management server.<br/>If not given, the value is inherited from HTTP options. Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--https-management-certificate-key-file`<br/>**Env:** `KC_HTTPS_MANAGEMENT_CERTIFICATE_KEY_FILE` | _File_ |  |
| **`https-management-certificates-reload-period`**<br/>Interval on which to reload key store, trust store, and certificate files referenced by https-management-* options for the management server.<br/>May be an ISO 8601 duration value, an integer number of seconds, or an integer followed by one of [ms, h, m, s, d]. Must be greater than 30 seconds. Use -1 to disable. If not given, the value is inherited from HTTP options. Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--https-management-certificates-reload-period`<br/>**Env:** `KC_HTTPS_MANAGEMENT_CERTIFICATES_RELOAD_PERIOD` | _String_ | `1h` |
| **`https-management-client-auth`**<br/>Configures the management interface to require/request client authentication.<br/>If not given, the value is inherited from HTTP options. Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--https-management-client-auth`<br/>**Env:** `KC_HTTPS_MANAGEMENT_CLIENT_AUTH` | `none`, `request`, `required` | `none` |
| **`https-management-key-store-file`**<br/>The key store which holds the certificate information instead of specifying separate files for the management server.<br/>If not given, the value is inherited from HTTP options. Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--https-management-key-store-file`<br/>**Env:** `KC_HTTPS_MANAGEMENT_KEY_STORE_FILE` | _File_ |  |
| **`https-management-key-store-password`**<br/>The password of the key store file for the management server.<br/>If not given, the value is inherited from HTTP options. Relevant only when something is exposed on the management interface - see the guide for details.<br/>**CLI:** `--https-management-key-store-password`<br/>**Env:** `KC_HTTPS_MANAGEMENT_KEY_STORE_PASSWORD` | _String_ | `password` |
| **`legacy-observability-interface`**<br/>If metrics/health endpoints should be exposed on the main HTTP server (not recommended).<br/>If set to true, the management interface is disabled.<br/>**CLI:** `--legacy-observability-interface`<br/>**Env:** `KC_LEGACY_OBSERVABILITY_INTERFACE` | `true`, `false` | `false` |
