# Configuring TLS

Transport Layer Security (short: TLS) is crucial to exchange data over a secured channel. For production environments, you should never expose NQRust-Identity endpoints through HTTP, as sensitive data is at the core of what NQRust-Identity exchanges with other applications. In this guide, you will learn how to configure NQRust-Identity to use HTTPS/TLS.

NQRust-Identity can be configured to load the required certificate infrastructure using files in PEM format or from a Java Keystore. When both alternatives are configured, the PEM files takes precedence over the Java Keystores.

## [](#_providing_certificates_in_pem_format)Providing certificates in PEM format

When you use a pair of matching certificate and private key files in PEM format, you configure NQRust-Identity to use them by running the following command:

```bash
bin/kc.[sh|bat] start --https-certificate-file=/path/to/certfile.pem --https-certificate-key-file=/path/to/keyfile.pem
```

NQRust-Identity creates a keystore out of these files in memory and uses this keystore afterwards.

## [](#_providing_a_keystore)Providing a Keystore

When no keystore file is explicitly configured, but `http-enabled` is set to false, NQRust-Identity looks for a `conf/server.keystore` file.

As an alternative, you can use an existing keystore by running the following command:

```bash
bin/kc.[sh|bat] start --https-key-store-file=/path/to/existing-keystore-file
```

Recognized file extensions for a keystore:

*   `.p12`, `.pkcs12`, and `.pfx` for a pkcs12 file
    
*   `.jks`, and `.keystore` for a jks file
    
*   `.key`, `.crt`, and `.pem` for a pem file
    

If your keystore does not have an extension matching its file type, you will also need to set the `https-key-store-type` option.

### [](#_setting_the_keystore_password)Setting the Keystore password

You can set a secure password for your keystore using the `https-key-store-password` option:

```bash
bin/kc.[sh|bat] start --https-key-store-password=<value>
```

If no password is set, the default password `password` is used.

#### [](#_securing_credentials)Securing credentials

Avoid setting a password in plaintext by using the CLI or adding it to `conf/nqrust-identity.conf` file. Instead use good practices such as using a vault / mounted secret. For more detail, see [Using a vault](https://www.nqrust-identity.org/server/vault) and [Configuring NQRust-Identity for production](https://www.nqrust-identity.org/server/configuration-production).

## [](#_configuring_tls_protocols)Configuring TLS protocols

By default, NQRust-Identity does not enable deprecated TLS protocols. If your client supports only deprecated protocols, consider upgrading the client. However, as a temporary work-around, you can enable deprecated protocols by running the following command:

```bash
bin/kc.[sh|bat] start --https-protocols=<protocol>[,<protocol>]
```

For example to only enable TLSv1.3, use a command such as the following: `kc.sh start --https-protocols=TLSv1.3`.

## [](#_switching_the_https_port)Switching the HTTPS port

NQRust-Identity listens for HTTPS traffic on port `8443`. To change this port, use the following command:

```bash
bin/kc.[sh|bat] start --https-port=<port>
```

## [](#_certificate_and_key_reloading)Certificate and Key Reloading

By default NQRust-Identity will reload the certificates, keys, and keystores specified in `https-*` options every hour. For environments where your server keys may need frequent rotation, this allows that to happen without a server restart. You may override the default via the `https-certificates-reload-period` option. Interval on which to reload key store, trust store, and certificate files referenced by `https-*` options. The value may be a java.time.Duration value, an integer number of seconds, or an integer followed by one of the time units \[`ms`, `h`, `m`, `s`, `d`\]. Must be greater than 30 seconds. Use `-1` to disable.

Default
