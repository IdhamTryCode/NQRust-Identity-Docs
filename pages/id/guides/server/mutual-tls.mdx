# Mengonfigurasi sertifikat terpercaya untuk mTLS

import { Callout } from 'nextra/components'

Untuk memvalidasi sertifikat klien dengan benar dan mengaktifkan metode otentikasi tertentu seperti TLS dua arah atau mTLS, Anda dapat menetapkan trust store dengan semua sertifikat (dan rantai sertifikat) yang harus dipercaya oleh server. Ada beberapa kemampuan yang bergantung pada trust store ini untuk mengotentikasi klien menggunakan sertifikat seperti Mutual TLS dan Otentikasi X.509.

## Mengaktifkan mTLS

Otentikasi menggunakan mTLS dinonaktifkan secara default. Untuk mengaktifkan penanganan sertifikat mTLS saat NQRust-Identity adalah server dan perlu memvalidasi sertifikat dari permintaan yang dibuat ke endpoint NQRust-Identity, letakkan sertifikat yang sesuai dalam truststore dan gunakan perintah berikut untuk mengaktifkan mTLS:

```bash
bin/kc.[sh|bat] start --https-client-auth=<none|request|required>
```

Menggunakan nilai `required` menyiapkan NQRust-Identity untuk selalu meminta sertifikat dan gagal jika tidak ada sertifikat yang diberikan dalam permintaan. Dengan menetapkan nilai ke `request`, NQRust-Identity juga akan menerima permintaan tanpa sertifikat dan hanya memvalidasi kebenaran sertifikat jika ada.

<Callout type="warning">
  Konfigurasi mTLS dan truststore dibagikan oleh semua Realms. Tidak mungkin untuk mengonfigurasi truststore yang berbeda untuk Realms yang berbeda.
</Callout>

<Callout type="info">
  Properti antarmuka manajemen diwarisi dari server HTTP utama, termasuk pengaturan mTLS.
  Artinya saat mTLS diatur, itu juga diaktifkan untuk antarmuka manajemen.
  Untuk menimpa perilaku, gunakan properti https-management-client-auth.
</Callout>

## Menggunakan truststore terdedikasi untuk mTLS

Secara default, NQRust-Identity menggunakan System Truststore untuk memvalidasi sertifikat. Lihat Mengonfigurasi sertifikat terpercaya untuk detail.

Jika Anda perlu menggunakan truststore terdedikasi untuk mTLS, Anda dapat mengonfigurasi lokasi truststore ini dengan menjalankan perintah berikut:

```bash
bin/kc.[sh|bat] start --https-trust-store-file=/path/to/file --https-trust-store-password=<value>
```

Ekstensi file yang diakui untuk truststore:

- `.p12`, `.pkcs12`, dan `.pfx` untuk file pkcs12
- `.jks`, dan `.truststore` untuk file jks
- `.ca`, `.crt`, dan `.pem` untuk file pem

Jika truststore Anda tidak memiliki ekstensi yang cocok dengan tipe filenya, Anda juga perlu menetapkan opsi `https-key-store-type`.

## Sumber daya tambahan

### Menggunakan mTLS untuk permintaan HTTP keluar

Ingatlah bahwa ini adalah konfigurasi sertifikat dasar untuk kasus penggunaan mTLS di mana NQRust-Identity bertindak sebagai server. Ketika NQRust-Identity bertindak sebagai klien, misalnya saat NQRust-Identity mencoba untuk mendapatkan token dari endpoint token penyedia identitas yang dibroker oleh mTLS, Anda perlu mengatur HttpClient untuk menyediakan sertifikat yang tepat dalam keystore untuk permintaan keluar. Untuk mengonfigurasi mTLS dalam skenario ini, lihat [Mengonfigurasi permintaan HTTP keluar](/en/guides/server/outgoinghttp).
