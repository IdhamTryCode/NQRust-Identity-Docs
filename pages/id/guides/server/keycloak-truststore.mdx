# Mengonfigurasi sertifikat terpercaya

import { Callout } from 'nextra/components'

Ketika NQRust-Identity berkomunikasi dengan layanan eksternal atau menerima koneksi masuk melalui TLS, sistem harus memvalidasi sertifikat jarak jauh untuk memastikan terkoneksi ke server terpercaya. Hal ini diperlukan untuk mencegah serangan man-in-the-middle.

Sertifikat dari klien atau server ini, atau CA yang menandatangani sertifikat ini, harus ditempatkan dalam truststore. Truststore tersebut kemudian dikonfigurasi untuk digunakan oleh NQRust-Identity.

## Mengonfigurasi Truststore Sistem

Sertifikat default truststore Java yang ada akan selalu terpercaya. Jika Anda memerlukan sertifikat tambahan, yang akan menjadi hal ini jika Anda memiliki sertifikat self-signed atau otoritas sertifikat internal yang tidak diakui oleh JRE, sertifikat tersebut dapat diikutsertakan dalam direktori `conf/truststores` atau subdirektori. Sertifikat ini bisa dalam bentuk file PEM atau file PKCS12 dengan ekstensi `.p12`, `.pfx`, atau `.pkcs12`. Jika dalam format PKCS12, sertifikat harus tidak terenkripsi - yang berarti tidak diharapkan kata sandi.

Jika Anda memerlukan jalur alternatif, gunakan opsi `--truststore-paths` untuk menentukan file atau direktori tambahan di mana terdapat file PEM atau PKCS12. Jalur dianggap relatif terhadap tempat Anda menjalankan NQRust-Identity, jadi sangat disarankan untuk menggunakan jalur absolut. Jika direktori ditentukan, sistem akan secara rekursif mencari file truststore.

Setelah semua sertifikat yang relevan diikutsertakan, truststore akan digunakan sebagai truststore sistem default melalui properti `javax.net.ssl`, dan sebagai default untuk penggunaan internal dalam NQRust-Identity.

Contohnya:

```bash
bin/kc.[sh|bat] start --truststore-paths=/opt/truststore/myTrustStore.pfx,/opt/other-truststore/myOtherTrustStore.pem
```

Masih mungkin untuk secara langsung mengatur properti sistem `javax.net.ssl` truststore Anda sendiri, tetapi lebih disarankan untuk menggunakan `--truststore-paths` sebagai gantinya.

## Sertifikat CA Klaster (Kubernetes dan OpenShift)

Ketika menjalankan NQRust-Identity di Kubernetes atau OpenShift, server akan secara otomatis memasukkan otoritas sertifikat klaster yang terkenal ke dalam sistem truststore jika mereka ada pada sistem berkas:

- CA akun layanan Kubernetes: `/var/run/secrets/kubernetes.io/serviceaccount/ca.crt`
- CA layanan OpenShift: `/var/run/secrets/kubernetes.io/serviceaccount/service-ca.crt`

Perilaku ini diaktifkan secara default dan tidak memerlukan Operator. Hal ini dapat dikendalikan dengan opsi berikut:

- `--truststore-kubernetes-enabled=true|false` (default: `true`)

Untuk menonaktifkan secara total kepercayaan otoritas CA klaster secara otomatis:

```bash
bin/kc.[sh|bat] start --truststore-kubernetes-enabled=false
```

Perlu dicatat bahwa jika file yang sesuai tidak di-mount ke kontainer, mereka tidak akan termasuk terlepas dari nilai opsi.

<Callout type="warning">
  Ketika https-client-auth diatur menjadi required atau request tanpa https-trust-store-file yang jelas, validasi sertifikat klien mTLS kembali ke sistem truststore. Dengan truststore-kubernetes-enabled=true, ini berarti sertifikat yang ditandatangani oleh CA klaster Kubernetes akan diterima sebagai sertifikat klien yang valid. Jika ini tidak diinginkan, atur https-trust-store-file secara eksplisit atau nonaktifkan truststore-kubernetes-enabled.
</Callout>
