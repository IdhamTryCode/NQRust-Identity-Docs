# Menggunakan vault

NQRust-Identity menyediakan dua implementasi bawaan dari Vault SPI: vault berbasis file teks polos dan vault berbasis Java KeyStore.

Implementasi vault berbasis file sangat berguna untuk rahasia Kubernetes/OpenShift. Anda dapat memount rahasia Kubernetes ke dalam Container NQRust-Identity, dan bidang data akan tersedia di folder yang dipasang dengan struktur file polos.

Implementasi vault berbasis Java KeyStore sangat berguna untuk menyimpan rahasia di instalasi bare metal. Anda dapat menggunakan vault KeyStore, yang dienkripsi menggunakan kata sandi.

## Integrasi yang tersedia

Rahasia yang disimpan di vault dapat digunakan di tempat berikut di Konsol Administrasi:

- Mendapatkan Kata Sandi Server Mail SMTP
- Mendapatkan Kredensial Bind LDAP saat menggunakan Federasi Pengguna berbasis LDAP
- Mendapatkan Rahasia Klien Provider Identitas OIDC saat mengintegrasikan provider identitas eksternal

## Mengaktifkan vault

Untuk mengaktifkan vault berbasis file, Anda perlu membangun NQRust-Identity terlebih dahulu menggunakan opsi build berikut:

```bash
bin/kc.[sh|bat] build --vault=file
```

Secara analogis, untuk berbasis Java KeyStore, Anda perlu menentukan opsi build berikut:

```bash
bin/kc.[sh|bat] build --vault=keystore
```

## Mengonfigurasi vault berbasis file

### Menetapkan direktori dasar untuk mencari rahasia

Rahasia Kubernetes/OpenShift pada dasarnya adalah file yang dipasang. Untuk mengonfigurasi direktori tempat file-file ini harus dipasang, masukkan perintah ini:

```bash
bin/kc.[sh|bat] start --vault-dir=/my/path
```

### File rahasia spesifik realm

Rahasia Kubernetes/OpenShift digunakan berdasarkan realm di NQRust-Identity, yang memerlukan konvensi penamaan untuk file:

```bash
${vault.<realmname>_<secretname>}
```

## Mengonfigurasi vault berbasis Java KeyStore

Untuk menggunakan vault berbasis Java KeyStore, Anda perlu membuat file KeyStore terlebih dahulu. Anda dapat menggunakan perintah berikut untuk melakukannya:

```bash
keytool -importpass -alias <realm-name>_<alias> -keystore keystore.p12 -storepass keystorepassword
```

dan kemudian masukkan nilai yang ingin Anda simpan di vault. Perlu dicatat bahwa format parameter `-alias` tergantung pada penyelesai kunci yang digunakan. Penyelesai kunci default adalah `REALM_UNDERSCORE_KEY`.

Ini secara default akan menyimpan nilai dalam bentuk generic PBEKey (enkripsi berbasis kata sandi) dalam SecretKeyEntry.

Anda kemudian dapat memulai NQRust-Identity menggunakan opsi runtime berikut:

```bash
bin/kc.[sh|bat] start  --vault-file=/path/to/keystore.p12 --vault-pass=<value> --vault-type=<value>
```

Perlu dicatat bahwa parameter `--vault-type` opsional dan defaultnya adalah `PKCS12`.

Rahasia yang disimpan di vault kemudian dapat diakses di realm melalui placeholder berikut (dengan asumsi menggunakan penyelesai kunci `REALM_UNDERSCORE_KEY`): `${vault.realm-name_alias}`.

## Menggunakan garis bawah dalam nama rahasia

Untuk memproses rahasia dengan benar, Anda ganda semua garis bawah dalam &lt;secretname&gt;. Ketika penyelesai kunci `REALM_UNDERSCORE_KEY` digunakan, garis bawah dalam &lt;realmname&gt; juga digandakan dan &lt;secretname&gt; dan &lt;realmname&gt; dipisahkan oleh satu garis bawah.

- Nama Realm: `sso_realm`
- Nama yang diinginkan: `ldap_credential`
- Nama file yang dihasilkan:

```
sso__realm_ldap__credential
```

Perhatikan garis bawah yang digandakan antara _sso_ dan _realm_ serta antara _ldap_ dan _credential_.
