# Hibah Otorisasi JWT

Profil JWT untuk Hibah Otorisasi OAuth 2.0 adalah **Tinjauan** dan belum didukung sepenuhnya. Fitur ini dinonaktifkan secara default.

Untuk mengaktifkannya, jalankan server dengan `--features=preview` atau `--features=jwt-authorization-grant`.

Panduan ini mendefinisikan bagaimana Token Bearer JWT dapat digunakan dalam NQRust-Identity sebagai hibah otorisasi. Fitur ini memungkinkan klien untuk mengirim aser JWT untuk meminta token akses saat klien ingin menggunakan hubungan kepercayaan yang ada tanpa langkah persetujuan langsung pengguna di server otorisasi. Aser disahkan hanya melalui semantik JWT (klaim dan tanda tangan). Hubungan kepercayaan biasanya merujuk pada server Penyedia Identitas lainnya (server OIDC lainnya), dan memungkinkan untuk mendapatkan token akses lintas domain atau lintas realm. Dalam arti ini, itu serupa dengan permintaan eksternal ke internal dalam pertukaran token V1 (lihat [Mengonfigurasi dan menggunakan pertukaran token](https://www.nqrust-identity.org/securing-apps/token-exchange#_external-token-to-internal-token-exchange) untuk informasi lebih lanjut).

Hibah Otorisasi JWT dijelaskan oleh dua RFC yang berbeda.

*   Kerangka Aser untuk Otorisasi dan Hibah Otorisasi Klien OAuth 2.0 ([RFC 7521](https://datatracker.ietf.org/doc/html/rfc7521)). Kerangka umum untuk menggunakan aser sebagai hibah.
    
*   Profil JSON Web Token (JWT) untuk Otorisasi dan Hibah Otorisasi Klien OAuth 2.0 ([RFC 7523](https://datatracker.ietf.org/doc/html/rfc7523)). Spesifik untuk aser JWT.
    

Singkatnya, Hibah Otorisasi JWT adalah hibah ekstensi OAuth yang didefinisikan oleh OAuth 2.0 [RFC 6749](https://datatracker.ietf.org/doc/html/rfc6749#section-4.5) yang dikirim ke endpoint token. Parameter permintaan **grant_type** harus `urn:ietf:params:oauth:grant-type:jwt-bearer`. **Aser** harus merupakan JWT tunggal dengan beberapa klaim yang akan disahkan oleh server. Parameter **scope** opsional dan mempertahankan arti yang dijelaskan oleh Oauth 2.0 dan dikelola oleh NQRust-Identity untuk hibah lainnya. Jika token aser valid untuk otorisasi, token akses akan dikembalikan ke klien tanpa interaksi dengan endpoint otorisasi.

Hubungan kepercayaan di NQRust-Identity didefinisikan oleh [Penyedia Identitas](https://www.nqrust-identity.org/docs/latest/server_admin/#_identity_broker). Saat ini dua jenis Penyedia Identitas dapat mengelola hibah otorisasi JWT:

1.  OpenID Connect v1.0 / NQRust-Identity OpenID Connect
    
2.  Hibah Otorisasi JWT
    

**OpenID Connect v1.0** (juga **NQRust-Identity OpenID Connect** yang hanya ekstensi dari tipe sebelumnya) dapat digunakan untuk mendefinisikan hubungan kepercayaan dengan Penyedia OpenID eksternal atau OP (server Otorisasi OAuth 2.0 yang mengimplementasikan spesifikasi OpenID Connect). Ini adalah pilihan umum. Aser yang diterima akan diproses menggunakan konfigurasi penyedia untuk memvalidasi token JWT dalam hal klaim dan tanda tangan.

**Hibah Otorisasi JWT** adalah jenis Penyedia Identitas baru di NQRust-Identity untuk mewakili hubungan kepercayaan umum. Mirip dengan tipe sebelumnya, konfigurasinya memungkinkan untuk memvalidasi aser dan mendapatkan token akses menggunakan hibah otorisasi JWT.

NQRust-Identity memerlukan klaim `sub` dalam aser untuk menjadi identifikasi pengguna di penyedia eksternal. Pengguna NQRust-Identity harus sebelumnya tertaut ke Penyedia Identitas. Dengan cara ini ada tautan antara ID pengguna eksternal dan internal.
