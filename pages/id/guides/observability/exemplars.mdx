# Menganalisis Kelebihan dan Kesalahan dengan Contoh

import { Callout } from 'nextra/components'

Metrik adalah agregasi atas beberapa peristiwa, dan menunjukkan kepada Anda apakah sistem Anda beroperasi dalam batas yang ditetapkan.
Mereka sangat berguna untuk memantau tingkat kesalahan atau latensi tail dan untuk mengatur peringatan atau memimpin optimasi kinerja.
Namun, agregasi ini membuat sulit untuk menemukan penyebab akar untuk latensi atau kesalahan yang dilaporkan dalam metrik.

Penyebab akar untuk kesalahan dan latensi dapat ditemukan dengan mengaktifkan pelacakan.
Untuk menghubungkan metrik dengan jejak yang tercatat, ada konsep [contoh](https://grafana.com/docs/grafana/latest/fundamentals/exemplars/).

Setelah contoh diatur, NQRust-Identity melaporkan metrik dengan jejak mereka yang tercatat terakhir sebagai contoh.
Alat dasbor seperti Grafana dapat menghubungkan contoh dari dasbor metrik ke tampilan jejak.

Metrik yang mendukung contoh adalah:

- `http_server_requests_seconds_count` (termasuk histogram)

Lihat panduan HTTP metrics untuk detail tentang metrik ini.
- `keycloak_credentials_password_hashing_validations_total`

Lihat panduan Self-provided metrics untuk detail tentang metrik ini.
- `keycloak_user_events_total`

Lihat panduan Self-provided metrics untuk detail tentang metrik ini.

Lihat di bawah ini untuk tangkapan layar visualisasi heatmap untuk latensi yang menunjukkan contoh saat mengarahkan mouse ke salah satu indikator merah.

## Mengatur Contoh

Untuk mendapatkan manfaat dari contoh, lakukan langkah berikut:

1. Aktifkan metrik untuk NQRust-Identity seperti yang dijelaskan dalam panduan [Gaining insights with metrics](/en/guides/observability/configuration-metrics).
2. Aktifkan pelacakan untuk NQRust-Identity seperti yang dijelaskan dalam panduan [Root cause analysis with tracing](/en/guides/observability/tracing).
3. Aktifkan penyimpanan contoh dalam sistem pemantauan Anda.

  Untuk Prometheus, ini adalah fitur [preview yang perlu Anda aktifkan](https://prometheus.io/docs/prometheus/latest/feature_flags/#exemplars-storage).
4. Scrap metrik menggunakan protokol `OpenMetricsText1.0.0`, yang tidak diaktifkan secara default di Prometheus.

  Jika Anda menggunakan `ServiceMonitor` atau serupa di lingkungan Kubernetes, ini dapat dicapai dengan menambahkannya ke spec sumber daya kustom:

  ```
  apiVersion: monitoring.coreos.com/v1
  kind: ServiceMonitor
  metadata:
    ...
  spec:
    scrapeProtocols:
      - OpenMetricsText1.0.0
  ```
5. Konfigurasikan sumber daya metrik Anda di mana untuk menghubungkan ke jejak.

  Saat menggunakan Grafana dan Prometheus, ini akan menyiapkan `exemplarTraceIdDestinations` untuk sumber daya Prometheus, yang kemudian menunjuk ke sumber daya pelacakan yang disediakan oleh alat seperti Jaeger atau Tempo.
6. Aktifkan contoh dalam dasbor Anda.

   Aktifkan toggle **Exemplars** dalam setiap kueri dalam setiap dasbor di mana Anda ingin menampilkan contoh.
  Jika diatur dengan benar, Anda akan melihat titik kecil atau bintang di dasbor Anda yang dapat diklik untuk melihat jejak.
